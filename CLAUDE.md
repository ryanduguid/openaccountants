# OpenAccountants — Agent Instructions

Read this before writing or committing anywhere in this repository.

## What this repository is

- A library of open-source **Tax Guides** ("skills"): plain-markdown tax rules per jurisdiction, one file each with YAML frontmatter, structured so an AI agent can read and apply them. Two quality states only: `tier: 1` accountant-reviewed (a named licensed accountant signed off) and `tier: 2` source-cited draft.
- **This is `ryanduguid/openaccountants`, a fork of `openaccountants/openaccountants`.** Upstream rewrote its history, so the two share no commits and nothing syncs between them. Work here lands on this repo's `main` through pull requests. The hosted MCP endpoint (`openaccountants.com/api/mcp`), the website, the Calendly booking link in guide footers and the PyPI package are upstream's and are not operated from here; any doc that says a "platform sync" writes into this repo describes upstream's retired process. `README.md` states the fork's current status.
- To use the guides rather than edit them: read `index.json` (the `counts` block gives guide, jurisdiction and accountant-reviewed totals), then load `packages/<jurisdiction>/`, which are self-contained bundles. `llms.txt` is the short agent-facing entry point. Derive every count from `index.json`; do not quote numbers from memory or from other docs.
- Mixed licence: software is AGPL-3.0-only; the Guides (`skills/`, `packages/`, `workflows/`, `index.json`, `llms*.txt`) are under the source-available OA Guide License. See `LICENSING.md` and `REUSE.toml`.

## The editing loop, for every change under `skills/`

1. Edit the source guide in `skills/`. Never hand-edit `packages/` (except `us-federal/`), `index.json` or `llms-full.txt`.
2. If the body changed, advance `last_updated` (`YYYY-MM-DD`, never backwards) or `version` (numeric, and it must match any `vX.Y` in a body heading). `scripts/check-sync-integrity.py --strict-metadata` fails the PR otherwise.
3. Regenerate and commit the derived trees in the same change:

   ```
   python3 scripts/build-packages.py && python3 scripts/build-index.py && python3 scripts/build-llms-full.py
   ```

   Nothing else rebuilds them. CI's `guard-derived-trees` job rebuilds all three into a temp dir and fails on any difference; `python3 scripts/validate-guides.py --derived-only` is the same check locally. Expect a large diff: a foundation or federal edit touches every package that bundles it.
4. If `index.json`'s `counts` changed, update the figures that `scripts/check-coverage-claims.py` checks (the README headline, the derived table in `docs/COVERAGE.md`, the inventory in `docs/QUALITY-TIERS.md`) and run it until it reports 0 disagreements. It is a review aid, not a CI gate.
5. Run the checks below before pushing.

## Frontmatter and body rules

- **The frontmatter spec is `docs/skill-template.md`.** Do not restate or improvise variants. CI (`scripts/validate-guides.py`) fails on malformed YAML; a missing `name` or `description`; a missing `jurisdiction` (a warning only inside `skills/cross-border/treaty-corridors`, `skills/intelligence`, `skills/templates` and `skills/international/eu`); a `tier` other than `1` or `2`; a missing or malformed `last_updated`; a `tax_year` that is not a bare integer 2015-2035 (ranges and fiscal calendars go in `tax_year_notes`); `tier: 1` without a real `reviewed_by` or `verified_by`; `tier: 2` with a real `verified_by`.
- `category` and `tax_year` are expected on new files but **not enforced**; `category` is absent from most of the corpus, so never join on it. `review_status` (`current` / `pending_review`) appears on most guides but is not part of the spec and is not validated. A `reviewed_by` name on a `tier: 2` guide does not make it reviewed.
- `name` becomes the index slug and the MCP slug: lowercase letters and digits separated by single hyphens, and **unique across the repo**. Grep for `^name: <slug>` before creating a guide. A US-state guide must not reuse a country prefix (`de-`, `ar-`, `co-` and `ma-` collide with Germany, Argentina, Colombia and Morocco).
- Body shape, matching the well-developed packs (Malta, UK, Germany, US-CA): scope, filing requirements, rates with citations, step-by-step computation, worked examples, edge cases, self-checks, provenance, disclaimer. Every rate, threshold and deadline cites a primary source (statute or tax authority); an aggregator such as a Big Four tax summary is corroboration, not a source. Worked-example arithmetic must recompute exactly, and every figure is labelled with its tax year.
- US guides load on top of `skills/foundation/us-tax-workflow-base.md`, which carries the Circular 230 §10.37 disclosure; other domains load their base from `skills/foundation/` (the list is in `CONTRIBUTING.md`). A `depends_on` entry must name a guide that exists: `scripts/validate-guides.py` checks every slug against the `name` of every guide under `skills/` and `packages/us-federal/`, whatever files the PR touched (the generated `foundation.md` is not a guide; name `workflow-base`). `scripts/build-packages.py` copies each foundation base a package's skills declare into that package.
- Every published guide ends with the `<!-- openaccountants-cta-block -->` marker followed by exactly one "Talk to a verified accountant" section; the canonical text lives in `scripts/cta_block.py`, and only `skills/templates/`, `skills/cross-border/treaty-corridors/_templates/` and `skills/integrations/` (platform guides, not tax guides) may omit it. `scripts/validate-guides.py` errors on a missing marker, a second section, or a marker that does not directly introduce the section; `python3 scripts/normalize-cta-block.py --apply` repairs all of that and stamps `last_updated`. Leave the block's text as it is.
- Flag positions that are actively litigated or aggressively audited with the exact marker `**AUDIT FLASH POINT**` (§174 R&D capitalization, §1402(a)(13) limited-partner SE after Soroban, §183 hobby loss, ERC clawbacks, BBA partnership audits, AB5 misclassification, and the like). Reviewers scan for it.

## Checks: what gates and what only advises

Install once: `python3 -m pip install -r scripts/requirements-validation.txt` (PyYAML) and, for the server tests, `python3 -m pip install ./mcp`. The tests run under the standard library's `unittest`; `pytest` also works but is not in any requirements file, so install it yourself if you want it. Run every script from the repository root: many of the review aids resolve paths relative to the working directory and silently report zero findings from anywhere else.

The CI gates, as `.github/workflows/` runs them:

```
python3 scripts/validate-guides.py                                  # frontmatter contract + derived-tree freshness
python3 scripts/validate-guides.py --changed-only --no-index-check  # PR mode; needs origin/main fetched
python3 scripts/check-sync-integrity.py --base "$(git merge-base origin/main HEAD)" --head HEAD --mode audit --strict-metadata
python3 -m unittest discover -s tests -p "test_*.py"                # (or `python3 -m pytest tests` once pytest is installed)
(cd mcp && python3 -m unittest discover -s tests -p "test_*.py")
```

`validate.yml` runs the first two (as `guard-derived-trees` and `validate`); `sync-integrity.yml` runs the rest; `no-ai-attribution.yml` enforces the commit policy below; CodeQL scans the workflows. Upstream's CLA bot (`cla.yml`) and its MCP mirror job (`sync-mcp.yml`) were removed from this fork: there is no CLA here, and nothing mirrors `packages/` anywhere.

Review aids: the other `scripts/check-*.py` and `scripts/list-*.py` files (arithmetic, bracket tables, fact conflicts, expired rules, stale futures, citation hosts, reviewer roster, ...) print findings and, except for `check-expired-rules.py`, always exit 0. Run the relevant ones whenever you touch rates or tables and read what they print; a clean exit code proves nothing. `check-cited-hosts.py` and `list-citation-rot.py` need network access.

## Commit and pull-request policy

- Commits carry the human author's identity. Do **not** add `Co-Authored-By: Claude` (or any AI) trailers, "Generated with Claude Code" lines, session links or similar AI-attribution lines to commit messages, and do not put them in the PR description: `no-ai-attribution.yml` fails the PR on any of them, in commit identities, commit messages or the description. Transparency about AI involvement belongs in README content and public posts, not in per-commit attribution.
- One logical change per commit; regenerated output travels with the source edit that caused it.
- There is no contributor licence agreement in this fork. The PR template's licensing checkbox records that the contribution is licensed under the licence of the files it changes (`CONTRIBUTING.md`, "Licensing of contributions"); it is the author's to tick.

## Annual update infrastructure

`packages/us-federal/rates.2025.json` and `rates.2026.json` carry all indexed federal amounts (brackets, SS wage base, retirement limits, FEIE, gift and estate, and so on). Guides cite the markdown for narrative; each December, maintainers refresh the rates JSON. See `packages/us-federal/ANNUAL-UPDATE-RUNBOOK.md`.

## When in doubt

Read the existing files in the same jurisdiction before writing new ones, and read `docs/REPO-LAYOUT.md` for any layout question; if another doc disagrees with it, REPO-LAYOUT wins and the other doc needs fixing. Match the pattern of the well-developed packs when filling in thinner countries, and prefer a few sourced facts over a full template of hedged ones.
