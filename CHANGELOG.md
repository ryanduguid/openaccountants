# Changelog

All notable changes to this repository, newest first, in the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) shape. The version line is the repository's, tagged `vX.Y.Z` on `main` ([CONTRIBUTING.md → Versions and tags](CONTRIBUTING.md#versions-and-tags)); the MCP server package keeps its own line in [mcp/CHANGELOG.md](mcp/CHANGELOG.md). Entries up to 2.3.0 are upstream's, from before this fork diverged; the pull-request numbers from 2.4.0 on are this repository's.

## [Unreleased]

The roadmap work that followed the September 2026 evaluation of this fork (pull requests #38 to #54): one source tree and one generated tree, gates instead of advice, and documentation that agrees with the corpus. Slugs and the `packages/` layout changed, so the next release is a major one.

### Added
- **Every indexed guide is packaged and served.** 57 of the 1,867 guides the index counted reached no package: the intake and return-assembly orchestrators of seven countries (a hand-kept map of twelve decided which were copied), the cross-border bundle's `us-expat/` set and the two Egypt treaty corridors (the bundle read only its top level and `treaty-corridors/`), Bermuda's corporate income tax guide (a redirect heuristic matched "consolidated revenue"), and the whole of `skills/financial-reporting/`, `skills/patterns/` and `skills/intelligence/`, which had no bundle. `scripts/build-packages.py` now finds orchestrators by jurisdiction code, packages every guide file, reads a domain bundle's subdirectories (a `_templates/` folder aside, and a basename two files share is prefixed with its folder), and builds `_financial-reporting`, `_patterns` and `_intelligence` beside the three bundles it had; the MCP catalogue test fails on any indexed guide the packages do not carry. Only the five file templates, the treaty-corridor template, the state references file and four workflow bases no guide declares stay unpackaged, by design. (#55)
- **A verification log beside a short methodology page.** `docs/ACCURACY-METHODOLOGY.md` had grown to 7,154 lines: 160 lines of methodology followed by a dated verification journal under 258 headings, valuable and unnavigable. It is now the methodology alone, and the journal is `docs/verification-log/`: one file per entry (114, of which 113 came from the journal and one from `COVERAGE.md`), named by the date of the commit that wrote it and its topic, the text as written, indexed in the directory's `README.md`. `tests/test_docs_links.py` now walks every markdown file under `docs/` and fails on an entry the index does not list, a listed file that does not exist, and any relative link or anchor that does not resolve. (#54)
- **`PARTNERS.md` is generated.** `scripts/build-partners.py` derives the roster of accountants on record from `index.json` with the one counting rule in `scripts/oa_tools/roster.py` (a guide is accountant-reviewed when it carries `tier: 1` and a reviewer's name; a named accountant is such a reviewer who did not ask to be anonymous), joined with the public-record links in `docs/partners.json`. `build-index.py` counts `accountant_reviewed` with the same rule, `build-llms-full.py` embeds the roster, `make build` runs the generator, and `scripts/check-coverage-claims.py` fails when the committed file differs from a fresh render or when `partners.json` names someone on no reviewed guide. The hand-maintained roster it replaces counted a name on any tier: it listed a reviewer whose five guides are all `tier: 2`, omitted four reviewers with 43 tier-1 guides between them, and kept "11 of 244 jurisdictions" on a scoreboard the tree never matched (it has accountant-reviewed guides in 24). (#54)
- **The coverage gate reads every headline.** `scripts/check-coverage-claims.py` checks the four-figure headline (guides, jurisdictions, accountant-reviewed, named accountants) in `README.md`, `llms.txt` and `docs/QUALITY-TIERS.md` with one regex and one rule, besides the derived table in `docs/COVERAGE.md`; `llms.txt` and `QUALITY-TIERS.md` carry the line for the first time. (#54)
- **Five gate checkers with baselines.** `scripts/oa_tools/findings.py` is the shared core: a finding with a stable fingerprint, `--json`, `--baseline`, `--no-baseline` and `--update-baseline`, and an exit code that fails on a finding the baseline does not list and on a baseline entry that no longer reproduces. `check-arithmetic.py`, `check-bracket-tables.py`, `check-expired-rules.py`, `check-fact-conflicts.py` and `check-coverage-claims.py` are built on it and run as the `gate-checkers` job together with `check-cited-hosts.py --selftest`; `make checkers` and `make baselines` drive them. Tests for `build-packages.py` (the 1,281-line generator that had none) and for `pdf_aes.py` against the FIPS-197 and SP 800-38A vectors. (#50)
- **`scripts/oa_tools/` and a `make`-based developer entry point.** The repository paths, guide discovery and the one frontmatter reader (tolerant and strict) in a package every script shares, replacing three copies of the block scanner and the `importlib` shims; `Makefile` (`install`, `build`, `bundle`, `validate`, `sync-check`, `checkers`, `baselines`, `test`, `check`) and `requirements-dev.txt`; pull-request runs cancel superseded ones, every job has a timeout and a pip cache; Dependabot watches both requirements files. (#49)
- **Validator rules.** Every `depends_on` slug must name a guide that exists (238 entries named bases no guide carried; `income-tax-workflow-base` and `social-contributions-workflow-base` were added to `skills/foundation/`); every published guide ends with exactly one marker-introduced CTA section (`scripts/normalize-cta-block.py --apply` repairs it; 591 guides carried a second section and 116 none) (#40); a duplicate `name` anywhere in the tree and a US-state guide outside the `us-<code>-` namespace are errors (#53); `review_status` must be `current` or `pending_review`, and `current` requires `tier: 1` (#56).
- **`START-HERE.md`** as a one-table quick-start, with `tests/test_docs_links.py` checking that every relative link and anchor in the root markdown and `docs/` resolves; the old stub linked two README headings deleted a month earlier (#42). **`mcp/tests/test_catalogue_integrity.py`** fails on an ambiguous or duplicate slug in the committed tree (#53).

- **Deleting or renaming a guide is recorded.** `scripts/check-sync-integrity.py --strict-metadata` refused every deletion or rename under `skills/` with "requires an explicit human-reviewed migration" and offered no way to provide one. `docs/guide-migrations.json` is that record: one entry per path (`from`, `to` or null, `slug`, `replacement`), reviewed in the pull request that adds it; the gate accepts a deletion or rename that the change adds to the record (an entry already present at the base authorises nothing, so a guide recreated at a migrated path needs its own review), requires a recorded move's destination to be a guide in the candidate, and still applies the metadata rules to a renamed guide whose body changed. This migration's 275 entries are the first. (#53)

Each package's `README.md` now lists the shared files it needs, `packages/bundles.json` records the same composition for tools (`{package: {jurisdiction, name, files, shared}}`), and `scripts/build-bundle.py` (`make bundle JURISDICTION=<package>`) assembles a package and its shared files into one upload-ready folder under `dist/bundles/`. `packages/_shared/README.md` states each file's source and how many packages list it. The MCP server catalogues the shared files under their declared jurisdictions, so no slug changed jurisdiction; a shared guide that declared none would be `GLOBAL`, never the code its neighbours declare most. `build-packages.py --us-only` is gone (a partial build cannot describe the whole tree) and an unknown option is now refused; `skills/cross-border/README.md` and `skills/verticals/README.md` are no longer copied into the bundles as if they were guides. `tests/test_build_bundle.py` pins the assembler and, on the committed tree, that every listed file exists, every package file is listed, every shared file is used and no guide is checked in twice.
